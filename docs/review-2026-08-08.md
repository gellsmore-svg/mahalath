# Mahalath — functional and code review

**Date:** 2026-08-08 · **Reviewed:** `master` @ `30f29c4`, version **1.2.0**
(one uncommitted change: a `license` field migration in `pyproject.toml`)
**Method:** the read paths were exercised against the **live 119-entry
`mahalath_rs_bachelor` corpus** (no mutating command was run against it), the
retrieval layer was probed adversarially, and then the source was read. Every
claim below is backed by a run or a query, reproduced inline.

---

## Part 1 — Functional review

**Baseline:** `481 passed, 0 skipped` in 198 s, against live MongoDB.
`ruff check src tests` clean, rule set pinned (`select = ["E4","E7","E9","F"]`)
with the explanatory comment, gated in CI.

### What works

The retrieval layer is the strongest part and it does what the README claims.
`mahalath retrieve "relational substrate"` returned frame-grouped definitions
with per-definition provenance and intent metadata, a transitive **reference
closure** (`MPL-004` pulled in because MPL-001's text cites it), and ranked
alternatives — exactly the shape described.

The budget invariant is documented as *"Budget pressure trims breadth and
verbosity in recorded steps; it never drops a frame or a closure node"*, and it
holds under adversarial input:

```
budget= 1500 entries=1 closure=1 degradations=[]
budget=  200 entries=1 closure=1 degradations=['alternatives_capped','provenance_dropped','closure_hardened']
budget=    1 entries=1 closure=1 degradations=['alternatives_capped','provenance_dropped','closure_hardened']
```

At a budget of **one token** it still returns the entry and its closure node, and
records which trims it applied. A documented guarantee that survives an absurd
input is rarer than it should be.

Security posture is honest and appropriate: `serve` binds `127.0.0.1`, the
module docstring says plainly there is no auth, there is no Docker file binding
`0.0.0.0`, and the hand-built HTML applies `html.escape` at every interpolation.
None of the Tirzah exposure problem exists here.

### Functional defects

All four measured against the live corpus.

#### F1. 44% of self-healing redefinitions change nothing — and still duplicate and still cascade

```
rem_redefine definitions written: 55
  of which byte-identical to a definition already present in the same frame: 24 (44%)
```

Each of those 24 appended a redundant definition **and** ran
`mark_dependents_stale()` across every dependent, which schedules those
dependents for their own redefine pass. Forty-four percent of the pass's writes
are model calls that produce no semantic change, grow the entry, and generate
downstream work.

The loop does settle — `stale` is currently 0 of 119 — so this is churn, not a
runaway. But it is churn in the subsystem the README leads with.

#### F2. 19% of entries carry an exact-duplicate definition inside one frame

```
entries=119  definitions=188
entries with an exact duplicate definition in the SAME frame: 23  (redundant defs: 24)
```

Polysemy is the system's central idea and frames are explicitly co-equal — but
two byte-identical strings under the same `context_id` are not two meanings.
`MPL-001` shows it directly:

```
Context [structural]
  [gemma4:e2b]                 The Relational Substrate is the specific substrate whose
                               constitution is fundamentally determined by relation.
  [rem_redefine (gemma4:e2b)]  The Relational Substrate is the specific substrate whose
                               constitution is fundamentally determined by relation.
  [gemma4:e2b]                 The Relational Substrate is the deepest, woven medium …
```

Because `build_bundle` never drops a frame, every retrieval touching one of those
23 entries spends budget rendering the same sentence twice.

#### F3. The self-healing path writes definitions with no audit link

The README states: *"Every model interaction is recorded with a
`decision_log_id` and queryable forever."* Measured:

```
definitions: 188
  decision_log_id null : 60  (32%)

normal debate path (n=133):  decision_log set 96%
rem_redefine path  (n=55):   decision_log set  0%
```

Every definition written by the redefine pass is unlinked from its decision log.
The debate path is at 96% and fine. So the audit chain is intact everywhere
except the one path that **changes an already-accepted meaning** — the change
most in need of a trail.

The interaction itself is presumably still in `decision_log` / `agent_exchanges`;
what is missing is the pointer from the definition to it, which is what makes it
queryable.

#### F4. 3 of 38 subcommands are documented, and errors dump the whole command list

```
$ grep -c "add_parser(" src/mahalath/cli.py   → 38
$ grep "add_parser(" … | grep -c "help="      →  3
```

And an argument error on a *subcommand* prints the **top-level** usage:

```
$ mahalath list-ontology --limit 5
usage: mahalath [-h]
                {db-ping,show-config,init,ingest-one,…39 names…}
mahalath: error: unrecognized arguments: --limit 5
```

Identical to Tirzah F5 — same argparse structure, same result. (`list-ontology`
takes no arguments at all; see F5.)

#### F5. `list-ontology` has no pagination

It emits all 119 entries as one JSON document and offers no `--limit`, `--skip`,
or filter. On a corpus of the size the README targets ("a legal code, an
engineering handbook, a research field's literature") this is unusable as an
inspection command.

#### F6. The default model adapter is a binary that isn't present

`config.example.yaml` sets `model_adapter: ollama_cli`, which shells out to an
`ollama` executable. On this machine Ollama is reachable over HTTP but the binary
is not on `PATH`. Same default, same consequence, as Tirzah F6 — worth fixing
once across both.

## Part 2 — Code review

### High

#### H1 · `staleness.py:1119-1138` — the redefine pass appends without checking for a no-op

```python
db.ontology_entries.update_one(
    {"_id": entry.mpl_label},
    {"$push": {"definitions": {
        "text": verdict.new_definition,
        "model_used": f"rem_redefine ({response.model})",
        "decision_log_id": None,
        "context_id": context_id,
        "consensus_score": None,
        "created_at": now,
    }}, "$set": {"updated_at": now}},
)
```

Nothing compares `verdict.new_definition` against the definitions already present
in the same `context_id`. When the model re-derives the same sentence — which it
did 44% of the time — the entry simply grows. Code side of F1 and F2.

**Fix:** before `$push`, compare normalised text within the frame. On a match,
refresh `updated_at`, clear stale, and return without appending or cascading.

#### H2 · `staleness.py:1141-1144` — the cascade fires even when nothing changed

```python
update_references(db, entry.mpl_label)
# A redefinition changes meaning downstream too …
mark_dependents_stale(db, entry.mpl_label, change_type="definition_redefined")
clear_stale(db, entry.mpl_label)
```

The comment's premise — *"a redefinition changes meaning downstream"* — is only
true when the definition actually changed. As written, a no-op redefine marks
every dependent stale, and each of those dependents then costs a redefine pass of
its own. This is the mechanism that turns H1's 24 duplicates into estate-wide
model spend.

Guarding H1 fixes this for free, since the early return skips the cascade.

#### H3 · `staleness.py:1129` — `decision_log_id: None` is hardcoded on the path that mutates meaning

The adjacent comment explains the intent (`model_used` names the author, added
after in-session frontier redefines exposed a gap), so this is a deliberate
trade rather than an oversight — but it trades away the wrong thing. Code side of
F3. `model_used` records *who* wrote it; `decision_log_id` is what lets an
operator retrieve *why*. On the debate path both are present; on the
self-healing path only the weaker one is.

**Fix:** the redefine already has a model `response` in scope — write a decision
log row for it and link it, as the debate path does.

### Medium

#### M1 · `consensus_score` is advertised per-definition and is absent for 85% of them

```
consensus_score absent : 129        (schema predates the field)
consensus_score null   :  31
  → no consensus score at all: 160 of 188 (85%)

normal debate path: set for 21%     rem_redefine path: set for 0%
```

Two different causes, and only one is a defect. The 0% on the REM path is
deliberate and correctly commented (*"Single-model verdict, not multi-agent
agreement — consensus_score is reserved for debate output"*). The 21% on the
debate path is schema evolution: the oldest definitions (2026-06-07) lack the key
entirely and the newest (2026-06-13) all carry it.

Neither is a bug. What is wrong is the README describing "per-definition
consensus score" as a property of the ontology when 85% of live definitions do
not have one and a whole pathway never will. Either backfill, or say which
pathway populates it.

#### M2 · `tests/test_staleness.py` — no test covers a redefinition that changes nothing

844 lines of staleness tests, three `noop` tests — and all three are about
unrelated no-ops (`retro_link_no_mentions`, `backfill_contexts_no_taxonomy`,
`redefine_intent_backfill_without_taxonomy`). None asserts what happens when
`verdict.new_definition` equals an existing definition, which is the single most
common real-world outcome at 44%.

This is the same shape found in the other three repos: the covering tests
exercise the arithmetic and the happy path, and the defect lives in a case no
test constructs.

#### M3 · `cli.py` — 2,755 lines, 38 subcommands, 3 described

Code side of F4/F5. The missing `help=` strings and the missing `--limit` are
both symptoms of a single-file CLI large enough that an omission is invisible.
Tirzah has the identical pattern at a larger scale (101 parsers, 9 documented);
worth solving once with a shared convention rather than twice by hand.

#### M4 · `pyproject.toml` — uncommitted license-metadata migration

```diff
-license = {file = "LICENSE"}
+license = "Apache-2.0"
+license-files = ["LICENSE"]
```

Correct for PEP 639 and newer setuptools, but it is sitting uncommitted in the
working tree, so a fresh clone builds with the old form. Land it or drop it.

### Low

#### L1 · Test suite takes 198 s against live MongoDB

481 tests, no skips, 3m18s. Correct in substance — testing an ontology store
against a real store is the right call — but it is slow enough to discourage
running locally, which is how a suite stops being a gate. Consider marking the
slower live tests so a fast subset exists.

#### L2 · `analysis.py` calibration headline depends on data the REM path doesn't write

The effectiveness report's headline is calibration — operator accept/reject
against the confidence the agent stated. Definitions written by the redefine path
carry neither `decision_log_id` nor `consensus_score` (H3, M1), so 32% of
definitions cannot participate in that analysis. The report does not say so.

## Comparison with the Hoglah, Deborah, Tirzah and Milcah reviews

Mahalath is the first of the five where the defects are **not** from either of
the two families the other reviews established.

- It does not do unanchored substring matching (Hoglah's `classify_error`,
  Deborah's `re.I` keywords, Milcah's markers).
- Its headline metrics are not degenerate constants (Hoglah's Prometheus
  counters, Milcah's `global_coherence`) — the effectiveness report is explicitly
  built to say "the threshold knobs are tuning noise" when the data says so.
- Its web posture is the honest one Tirzah's is not.

Its family is different and, for a *self-sustaining* system, more characteristic:
**a write path that does not check whether it is a no-op.** The redefine pass
recomputes, appends whatever it got, and cascades unconditionally. At 44% no-op
rate that converts a self-healing loop into a self-feeding one.

The property shared with all four siblings is still silence. A duplicate
definition, an unlinked audit row, a no-op cascade — none of them logs, warns, or
appears in the effectiveness report. The system is measuring its own
decision-making (`analysis.py`) while 32% of its writes are invisible to that
measurement.

## Suggested order

1. **H1 + H2** — one comparison before the `$push`, with the early return
   skipping the cascade. Fixes F1 and F2 together and stops the churn. Land with
   the M2 test (a redefine whose verdict equals the current definition must not
   append and must not cascade).
2. **H3** — write and link a decision log row on the redefine path. Restores the
   README's audit guarantee and unblocks L2.
3. **F2 cleanup** — a one-off de-duplication pass over the 23 affected entries,
   after H1 lands so it does not immediately re-accumulate.
4. **M1** — decide whether `consensus_score` is per-definition or per-pathway and
   make the README say that.
5. **F4/F5/M3** — `help=` strings, `--limit` on `list-ontology`, and the
   subcommand usage error. Shared with Tirzah; fix the convention once.
6. **M4, F6, L1** — small.

Nothing here is architectural. The ontology model, the frame-keyed polysemy, the
reference closure and the budget invariant are all sound and demonstrably work on
a real 119-entry corpus. The high findings are one missing equality check and one
missing audit write.
