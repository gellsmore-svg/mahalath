both log here so handoffs are visible. `.restart.md` remains the canonical
"current state" document — this file is the *how we got there*.

Convention for each entry:

```
## YYYY-MM-DD [agent]
<what was attempted, what was learned, what is next>
```

Older entries stay verbatim. If a claim turns out wrong, correct it in a
later entry rather than rewriting history.

and worked well there for codex/Claude coordination. If it stops working
for Mahalath, change it deliberately and note the change in a new entry.

**Conceptual relationship to Mnemosyne, flagged early:**

Mahalath and Mnemosyne share operating philosophy (local-first, MongoDB,
adapter boundary for swappable models, REM-style async consolidation,
multi-agent with bounded iteration, undecided/review queue, watched
ingest folder). The *purposes* are different: Mnemosyne is a memory
retrieval layer (given a question, find relevant content); Mahalath is
an ontology builder (given content, refine precise meanings).

Starting Mahalath fully independent so it does not carry a runtime
dependency on Mnemosyne's schemas. Cross-pollination should happen
through reading each other's code, not through imports. If a shared
library ever makes sense (e.g. for the Ollama adapter), it can be
extracted later.

Mnemosyne has already ingested as ~175k `ams_domain` nodes. Mahalath
should ingest fresh from the source files (Markdown), not depend on
