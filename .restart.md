# Mahalath Restart Notes

Last updated: 2026-06-06 (Stage 1 end-to-end landed)

## Status

**Stage 1 (first useful outcome) is complete and proven on a live document.**

Commands working:

- `mahalath db-ping` — MongoDB connectivity check.
- `mahalath show-config` — print loaded config as JSON.
- `mahalath ingest-one <path>` — read Markdown, SHA-256, dedupe, archive
  to `processed/`, write document record, emit an activity log.
- `mahalath process-document <document_id> [--max-terms N]` — extract
  candidate terms from the archived source, run the PrecisionCritic /
  SynthesisExplorer debate loop on the first N, persist accepted entries
  into the flat ontology (with MPL labels) or route undecided ones to
  the queue.
- `mahalath list-ontology` — JSON of accepted entries.

Modules in place under `src/mahalath/`:

- `config.py` — pydantic config tree with default + YAML loader.
- `labels.py` — MPL label parse / format / `next_top_level` /
  `next_child` / `next_variant`. Format: `MPL-NNN[.NNN[.NNN...]][a-z]?`.
- `db/` — MongoDB client factory, indexes, Pydantic models, repositories
  for six collections: `documents`, `ontology_entries` (`_id` = MPL
  label), `ontology_tree`, `decision_log`, `agent_exchanges`,
  `undecided_queue`.
- `adapters/` — `Adapter` protocol, `MockAdapter` for tests,
  `OllamaCliAdapter` shelling out to the Windows Ollama binary
  (`--nowordwrap --think=false --hidethinking --format json`,
  legacy-flag fallback).
- `extraction.py` — LLM-driven candidate term extraction, with a
  defensive "term must appear in document" filter that suppresses the
  gemma3:1b prompt-leak failure mode.
- `debate.py` — bounded multi-agent debate loop. `min(pc, se)` confidence
  per DQ-003. Accepted at threshold, undecided at iteration cap.
  Moderator is off in Stage 1 per DQ-001.
- `ontology.py` — `persist_debate_result`: MPL label assignment, write
  ontology entry + tree edge + decision log + per-iteration exchanges,
  route undecided to the queue.
- `ingestion.py` — `ingest_one`.
- `cli.py` — argparse entry point wiring the above.

Tests: **73 passing.** Includes live MongoDB round-trips against a
`mahalath_pytest` test database (dropped before and after).

Live end-to-end run (2026-06-06) against gemma3:1b on a short
pharmacology Markdown document:

- Ingestion: < 1 s.
- Two terms ("agonist", "receptor") debated to acceptance at confidence
  8.0 in 22 and 23 iterations (out of the **25** cap that was in force
  at smoke time) — ≈ 1 minute per term. Definitions are domain-correct.
- **Iteration cap raised to 50** post-smoke (per ADR-009 update); 25
  left almost no headroom and harder terms would have escalated to
  undecided without a real reason. Re-runs of agonist/receptor still
  accept at ~23 iter.
- 90 `agent_exchanges` records persisted (22 + 23 iterations × 2 agents).
- Activity logs at `logs/process-<document_id>-<utc_stamp>.md`.

## Next Step

Stage 2 candidates, roughly in priority order. Pick one to land next:

1. **Performance / model choice** — **done**: gemma4:e2b is the new
   default; 4.8× faster + better definitions. Could revisit if a
   stronger or smaller model is published, but not the blocker any more.
2. **First real corpus run** — **done** (2026-06-06): ingested
   `rs-cbo-beginner-v1.md`, 5 ontology entries accepted in 58.8 s
   (MPL-001 Ontology, MPL-002 Relational Substrate, MPL-003 Substrate,
   MPL-004 Continuity, MPL-005 Vortons). Surfaced two concrete
   priorities below (hierarchy + chunking) plus a style-prompt issue.
3. **Hierarchy emergence** — **first slice done** (2026-06-06):
   agent-callable Python actions (propose_parent / propose_alias /
   propose_merge / propose_split), an action_proposals audit
   collection, an ontology_reviews record per review pass, the
   hierarchy.py module that asks gemma4:e2b for structural actions, and
   process-document now runs a post-accept review per entry.
   Live run produced 5 entries + 6 action proposals; gemma4:e2b
   independently identified the Substrate / Relational Substrate
   relationship at confidence 8.5 but the slice's "no re-parenting"
   rule blocked the correct fix. Open: Stage 2.4 priorities below.
4. **Re-parenting at confidence ≥ 8.5** — **done** (2026-06-06).
   Validator no longer blocks already-parented children; apply path
   deletes the old tree edge before adding the new and records
   `previous_parent_label` for rollback; dispatcher picks the higher
   `reparent_threshold` (8.5) when the action would change an existing
   parent. Live re-run revealed the next problem (below).
5. **Multi-pass hierarchy consensus** — **done** (2026-06-06).
   `hierarchy_consensus_passes: int = 3` in RuntimeConfig;
   `run_hierarchy_review_consensus` runs review N times, returns only
   unanimously-agreed actions, confidence = min across passes.
   `--consensus-passes N` overrides for ad-hoc runs.
   **Live verification:** 3-pass consensus stabilised the
   Substrate / Relational Substrate direction (3/3 passes agreed RS
   → child of Substrate); cost was ~33% wall-clock overhead. Zero
   wrong-direction auto-applies in the run, vs one in the single-pass
   S2.4 run. Stage 2.6 candidates below.
6. **Operator CLI for proposals** — **done** (2026-06-06).
   `list-proposals --status STATUS`, `show-proposal`,
   `accept-proposal --note T`, `reject-proposal --note T`,
   `rollback-proposal --note T`. Accept revalidates at apply time so a
   stale proposal can no longer land if the world has moved; rollback
   reverses tree edges using the `previous_parent_label` stored at
   apply time. Live demonstrated on mahalath_dev: accepted RS→Substrate,
   rejected substrate→Ontology, rolled back CBO→Ontology.
7. **Heading-aware Markdown chunking** — **done** (2026-06-06).
   `chunk_markdown(text, max_chunk_chars=30000)` splits at H2; falls
   back to paragraph split on oversized sections; packs adjacent small
   sections. `extract_candidates_chunked()` aggregates + dedupes
   across chunks; filters against full document not chunk; one bad
   chunk no longer aborts the pipeline. Bachelor edition (270 KB) now
   runs end-to-end: 10 chunks → 100 candidates → 10 debated terms in
   5m42s, with 4 hierarchy actions auto-applied + 4 pending.
8. **Glossary export** — **done** (2026-06-06).
   `mahalath export-glossary [--format md|json] [--out PATH]` renders
   the live ontology as either a book-ready Markdown document or a
   schema-versioned JSON payload (`mahalath.glossary.v1`) with full
   provenance per entry (model attribution, decision_log_id, source
   document IDs).
7. **`process-input` watched folder + REM scheduler.** Automation —
   useful once the above are stable.

## Standing Rules

Carried from the operator pattern, applicable here by default until
contradicted:

- Keep semantic / ontology writes review-based at first; do not grant
  agents autonomous write authority before review queues and audit logs
  exist. (Done: every accepted entry has a `decision_log_id` linking
  back to its debate transcript; undecided queue exists.)
- Keep source preserved: do not silently rewrite, compress, or summarise
  source documents during ingestion. (Done: source bytes copied verbatim
  to `processed/`, SHA-256 verified post-copy.)
- Ask before implementing changes that alter source preservation, agent
  write authority, or any of the named "Out of scope" items in
  `docs/requirements-v0.1.md` §7.
