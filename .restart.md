## Status

**Stage 1 is complete and proven; Stage 2 is deep (through S2.39).**
The system ingests a corpus, debates precise definitions, grows a
hierarchy, tracks cross-references, self-heals stale entries, answers
grounded questions over the ontology, exports a glossary, serves a
retrieval API, annotates intent, and audits its own decision-making
nightly — all local-first against MongoDB + the Windows Ollama binary.

Tests: **388 passing** (was 73 at Stage 1 end). Includes live MongoDB
round-trips against a `mahalath_pytest` database (dropped before/after).

### Commands working (`mahalath <cmd>`)

Core pipeline:
- `db-ping`, `show-config`
- `ingest-one <path>` — SHA-256 dedupe, archive to `processed/`, record.
- `process-document <id> [--max-terms N] [--consensus-passes N]
  [--no-hierarchy-review]` — extract → debate → persist → hierarchy review.
- `process-input` — idempotent watched-folder scan + pipeline.
- `list-ontology`, `export-glossary [--format md|json] [--out PATH]`.
- `debate-one` — ad-hoc single-term debate.

Hierarchy / proposals:
- `list-proposals [--status S]`, `show-proposal`, `accept-proposal`,
  `reject-proposal`, `rollback-proposal` (revalidate-on-apply; rollback
  via stored `previous_parent_label`).

Definition contexts (polysemy) + intent taxonomy (I-A/I-B):
- `list-contexts [--kind frame|intent]`, `add-context <name> --description D
  [--kind frame|intent]`, `show-context <id|name>`,
  `seed-intents [--dry-run]` (idempotent standard illocution tags),
  `backfill-intents [--max-items N] [--apply] [--passes N] [--adapter A]
  [--model M]` — N-pass unanimity attribution, dry-run by default.
- `backfill-contexts [--max-items N] [--apply] [--adapter A] [--model M]`
  — walk untagged definitions, ask the model to frame each with one of
  the defined contexts; dry-run by default, `--apply` writes + refreshes
  the glossary. (S2.26.)

Staleness / self-healing:
- `list-stale`, `backfill-references`, `audit-stale`, `redefine-stale`.

Self-analysis (§3.4, S2.39):
- `effectiveness [--format text|json] [--snapshot]` — decision-
  effectiveness report: debate outcomes, operator-verdict-vs-agent-
  confidence calibration bands, undecided-queue health, re-debate
  resolution arcs, hierarchy-review yield, coverage, plus rule-based
  plain-language findings. `--snapshot` appends a JSON line to
  `logs/effectiveness.jsonl` (the REM nightly tail does this
  automatically).

Frontier review + serving:
- `frontier-review` — LLM adjudicator over the pending_review queue.
- `serve` (FastAPI web UI + `/api/chat`), `run`.

## Operational state (live databases)

All **9 Mahalath MongoDB databases are fully context-tagged**
(0 untagged definitions) as of 2026-06-10. Each carries the standard
three operator-authored contexts — `structural`, `theological`,
`physical` — with the RS-corpus descriptions. `gcse` and `rs_bachelor`
were already tagged; the other seven (`autoexport`, `bachelor`, `dev`,
`multi`, `pinput`, `rem`, `style`) had the contexts seeded and 28
definitions backfilled (all model-sourced, 0 errors) in the S2.26
follow-up run. See the 2026-06-10 session-log entries.

All **9 DBs also have materialised ancestor paths** (`OntologyEntry.path`)
as of 2026-06-11 — `backfill-paths` was run across every DB after the
S2.31 schema addition (rs_bachelor 100 entries unchanged from the live
S-A check; the rest filled where children existed). Idempotent.

**Stale backlog on rs_bachelor (found by the S2.39 effectiveness
report, 2026-06-12): 42 of 100 entries are flagged stale** — fallout
of the intent-rollout/redefine cascades. The nightly REM audit-stale
pass caps at 10 items/run, so either let ~4 nights clear it or run
`audit-stale` / `redefine-stale --max-items 42` manually against that
DB.

Default DB in `config.example.yaml` is `mahalath_dev`. The CLI has no
`--database` flag — select a DB by editing `config.yaml`, or call the
library functions directly with `cfg.mongo.database` set.

## Standing Rules

Carried from the operator pattern, applicable until contradicted:

- Keep semantic / ontology writes review-based; do not grant agents
  autonomous write authority before review queues and audit logs exist.
  (Done: every accepted entry has a `decision_log_id`; undecided +
  proposal queues exist.)
- Keep source preserved: do not silently rewrite, compress, or summarise
  source documents during ingestion. (Done: source bytes copied verbatim
  to `processed/`, SHA-256 verified post-copy.)
- Ask before implementing changes that alter source preservation, agent
  write authority, or any named "Out of scope" item in
  `docs/requirements-v0.1.md` §7.
